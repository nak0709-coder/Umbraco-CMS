# 1.1 Run Umbraco CMS Locally

This section guides you through running the Umbraco CMS host application (`src/Umbraco.Web.UI`) on your local machine using Kestrel or IIS Express, configuring launch profiles, and understanding the first-install experience. You will learn how to bootstrap the database and backoffice installer, as well as how configuration flows from the host into the Management and Delivery APIs and the backoffice UI.

## Prerequisites

- .NET 10 SDK installed
- SQL Server LocalDB or SQLite (default for development)
- (Optional) Visual Studio or VS Code for debugging

## Running the Application

Use the .NET CLI from the repository root to start the Umbraco host.

```bash
# Run with Kestrel (recommended)
dotnet run --project src/Umbraco.Web.UI

# Run with file-watcher for automatic rebuilds
dotnet watch --project src/Umbraco.Web.UI

# From Visual Studio:
#   Select the "Umbraco.Web.UI" profile to launch in debug mode
```

### Program.cs Entry Point

The `Program.cs` sets up the Umbraco builder, adds the backoffice and website (and optionally the Delivery API), composes custom components, and then boots Umbraco before running.

```csharp
WebApplicationBuilder builder = WebApplication.CreateBuilder(args);

builder.CreateUmbracoBuilder()
    .AddBackOffice()
    .AddWebsite()
#if UseDeliveryApi
    .AddDeliveryApi()
#endif
    .AddComposers()
    .Build();

WebApplication app = builder.Build();

await app.BootUmbracoAsync();

#if UseHttpsRedirect
app.UseHttpsRedirection();
#endif

app.UseUmbraco()
    .WithMiddleware(u =>
    {
        u.UseBackOffice();
        u.UseWebsite();
    })
    .WithEndpoints(u =>
    {
        u.UseBackOfficeEndpoints();
        u.UseWebsiteEndpoints();
    });

await app.RunAsync();
```

## Debug Profiles

Under `src/Umbraco.Web.UI/Properties/launchSettings.json` two launch profiles are defined:

```json
{
  "$schema": "https://json.schemastore.org/launchsettings.json",
  "profiles": {
    "IIS Express": {
      "commandName": "IISExpress",
      "launchBrowser": true,
      "environmentVariables": {
        "ASPNETCORE_ENVIRONMENT": "Development"
      }
    },
    "Umbraco.Web.UI": {
      "commandName": "Project",
      "launchBrowser": true,
      "environmentVariables": {
        "ASPNETCORE_ENVIRONMENT": "Development"
      },
      "applicationUrl": "https://localhost:44339;http://localhost:11000"
    }
  }
}
```

- IIS Express: http://localhost:11000 (SSL port 44339)
- Kestrel (“Umbraco.Web.UI”): https://localhost:44339 and http://localhost:11000

## Configuration Templates

Two JSON template files in the project root define the default and development configurations. On first build, these templates are copied to `appsettings.json` and `appsettings.Development.json` if those files do not already exist:

```xml
<Target Name="CopyAppsettingsTemplate" BeforeTargets="Build" Condition="!Exists('appsettings.json')">
  <Message Text="Copying appsettings.template.json to appsettings.json because it doesn't exist" Importance="high" />
  <Copy SourceFiles="appsettings.template.json" DestinationFiles="appsettings.json" />
</Target>
<Target Name="CopyAppsettingsDevelopmentTemplate" BeforeTargets="Build" Condition="!Exists('appsettings.Development.json')">
  <Message Text="Copying appsettings.Development.template.json to appsettings.Development.json because it doesn't exist" Importance="high" />
  <Copy SourceFiles="appsettings.Development.template.json" DestinationFiles="appsettings.Development.json" />
</Target>
```

## Initial Install Flow

1. On first run, if the database is not configured or no user exists, the runtime redirects to `/install`.
2. Navigate to `https://localhost:44339/install` to launch the installer SPA.
3. Complete the two-step wizard:- **Step 1**: Create your first backoffice user
- **Step 2**: Configure your database connection and run schema/data migrations

The installer context (`UmbInstallerContext`) orchestrates these steps client-side, while server-side `IInstallStep` implementations such as `DatabaseConfigureStep`, `DatabaseInstallStep`, and `CreateUserStep` perform the actual work under the covers.

## Runtime Configuration Flow

- Configuration values from **appsettings.json** and environment variables (e.g. connection strings, hosting settings) flow into the `IConfiguration` used by `Program.CreateBuilder(args)`.
- The Umbraco host sets the application’s **DataDirectory** (for SQLite file paths) and registers `IOptions<ConnectionStrings>`, `GlobalSettings`, and other option classes.
- Controllers in both the Management API and Delivery API consume these options via `IOptionsMonitor<T>` and `IHostingEnvironment` resolved from the DI container.
- The backoffice and installer frontends fetch their initial state through the server’s endpoints, which read the same runtime options under the hood.
